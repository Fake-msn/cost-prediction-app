# v1.9.0 — DuckDB excel 表格读取层 + CI/CD 门禁 + DuckDB 稳健加固

> 发布日期: 2026-10-09

## 新增特性 (Features)

### 表格数据处理 — DuckDB excel 读取层（本次核心）
- **`backend/excel_reader.py` 新模块**: 基于 DuckDB 官方 `excel` 扩展的 `read_xlsx` 读取层，`stop_at_empty=false` 防中部空行截断、`ignore_errors=true` 容错读取；**始终返回真实 `pandas.DataFrame`**——当扩展不可用（无网络 `INSTALL excel`）、`duckdb` 被 mock、或遇到 `.xls` 时，自动回退 `pd.read_excel(engine="openpyxl")`，调用方行为不变。
- **训练数据导入接入**: `data_loader.import_from_excel()` 的读取层由一次性全量载入的 `pd.read_excel(openpyxl)` 改为 `excel_reader.read_table()`，**清洗 / 质量过滤 / 字段映射逻辑完全保留**（仍先清洗再入库，不绕过清洗直接灌库）。
- **报表导出**: `export_dataframe_to_xlsx()` 经 `COPY ... TO xlsx` 产出基础 xlsx（无图表/富样式），扩展不可用时回退 `df.to_excel(openpyxl)`。
- **Docker 构建期预装扩展**: 根 `Dockerfile` 与 `deploy/modelscope/Dockerfile` 在构建期 best-effort 执行 `INSTALL excel; LOAD excel;`，下载失败不阻断构建，运行期离线 `LOAD` 即可，**无需引入 Node 等新运行时**。
- **按文件类型分流**（POC 实测结论落地）: 扁平历史表用 `read_xlsx`；合并单元格密集的 **BOQ 清单仍走 openpyxl**（`read_xlsx` 只保留合并区左上角值且不输出合并范围，`extract_boq.py` 规则 R1 依赖展开）；`.xls`（Excel 97-2003）保留 `xlrd`。

### CI/CD 自动化门禁
- **pytest + lint + Docker 构建验证 + 安全扫描**: 新增 PR/push 触发的 CI（Python 3.11/3.12 矩阵），含真实 DuckDB 引擎兼容性审计（`duckdb2_compat_audit.py`）、`tests_integration` 非 mock 集成门禁，以及 `Build Verification`（根 Dockerfile 构建 + 镜像内导入校验）。
- **安全扫描工作流**: Code Security Scan + Dependency Vulnerability Scan 作为独立门禁。

### ModelScope 部署纳管
- **`deploy/` 树纳入版本管理**: ModelScope 创空间部署资产首次入仓（`Dockerfile`、`deploy-modelscope.bat/.sh`、`ms_deploy.json`、`requirements-ms.txt`、`.dockerignore`、`README.md`）。`MODELSCOPE_TOKEN` 仅运行期从环境变量读取，未硬编码凭据。

## 问题修复 (Bug Fixes)

### 依赖版本
- **修复 openpyxl 与新版 pandas 的版本冲突**: CI 中 `pandas>=2.2.3` 解析到要求 `openpyxl>=3.1.5` 的新版，而依赖此前钉死 `openpyxl==3.1.2`，导致回退路径 `pd.read_excel(engine="openpyxl")` 抛 `ImportError`。放开下限至 `openpyxl>=3.1.5`（`requirements.txt` 与 `requirements-ms.txt` 同步）。
- **修复 excel_reader 回退在 mock 环境的行为**: `read_xlsx` 返回非 DataFrame（MagicMock）时判定为不可用并回退 pandas，单元测试环境不再误走快路径。

### DuckDB 存储/接口
- **DuckDB 2.0 升级评估落地**: 修复 H1–H7 历史问题（`init_duckdb` 建表、`project_meta` 补齐 `data_loader` 直接 SELECT 的列、`normalize_prices` 绑定参数折算、`prediction_uploads` 生命周期统一经 `data_loader` 串行化写锁 + 只读连接）与 N1/N2 新问题；配套真实引擎集成测试作为兼容性门禁。

### 前端
- **导航菜单选中态**: 修复半透明选中态与滚动高亮不一致（#5）。
- **移动端侧边栏**: 默认收起，避免小屏遮挡内容（#6）。

### 工具脚本
- **`push.bat` 增强**: 自动探测 8 个常见代理端口、支持 tag 推送、失败时给出中文错误指引（解决受限网络下 GitHub 推送超时）。

## 改进优化 (Improvements)

### 大表格读取性能（POC 实测，50 万行扁平 xlsx / 2GB 容器约束）
| 读取路径 | 耗时 | 峰值内存 | 完整行数 |
|---|---|---|---|
| `pd.read_excel(openpyxl)`（旧） | 65.0s | 660MB | 50 万（更大文件在 2GB 下 OOM/截断） |
| openpyxl `_parse_xlsx`（旧） | 56.3s | 697MB | 50 万 |
| `read_xlsx` staging 物化（新） | 4.6s | 151MB | 50 万 |
| 读取→SQL 清洗→入库 整链 | 5.7s | 257MB | 保留 450188 / 过滤 49812 |
| 读取→Python 分块清洗→批量入库 整链 | 9.7s | 294MB | 保留 450188 / 过滤 49812 |

- 结论：`read_xlsx` 较旧路径 **快 ~12–14×、省内存 ~4–8×**，"读取→清洗→入库"整链峰值 **≤294MB**，远低于 2GB 上限，解决"大体积表格经常读不全"的历史问题。
- 显式 `stop_at_empty=false`，空行改由清洗阶段 `name IS NOT NULL` 过滤，避免中途截断。

## 破坏性变更 (Breaking Changes)

- **openpyxl 依赖下限提升**: `openpyxl` 由 `==3.1.2` 调整为 `>=3.1.5`。升级后需重新 `pip install -r backend/requirements.txt`（`start.bat`/`start.sh` 会自动处理）。无 API / 数据格式 / 配置字段的不兼容变更。
